# 크레타 광고 플랫폼 구현 계획 (2026-08)

디지털 사이니지 광고(DOOH) 표준 구조를 크레타에 단계적으로 얹는다.
핵심 아이디어: **북 캔버스에 배치하는 「광고 위젯」이 판매 단위인 구좌(광고 슬롯)** 이고,
재생 시점에 편성 엔진이 활성 캠페인의 소재(이미지·영상)를 골라 순환 재생한다.
실제 플레이어가 없으므로 재생·편성·증빙은 미리보기/프레젠테이션 기반 시뮬레이션으로 구현한다.

## 업계 표준 대비 매핑

| 업계 개념                | 크레타 구현                                                                |
| ------------------------ | -------------------------------------------------------------------------- |
| 인벤토리/구좌(ad slot)   | 광고 위젯(adSlot) — 위젯 1개 = 구좌 1개, 슬롯 길이(초) 속성                |
| 광고주(advertiser)       | `creta_advertiser`                                                         |
| 캠페인(campaign, flight) | `creta_ad_campaign` — 기간(시작·종료), 상태, 가중치(SOV 전 단계), CPM 단가 |
| 소재(creative)           | `creta_ad_creative` — 이미지/영상, 업로드 미디어 재사용                    |
| 편성(rotation)           | 슬롯 길이 기준 공통 클록 라운드로빈(가중치 반영) → 2단계에서 SOV·시간대    |
| Proof of Play            | `creta_ad_play_log` — 보기 모드 재생 시 소재별 기록                        |
| 리포트/과금              | 캠페인별 노출수 집계 + 노출수 × CPM 정산(2단계 확장)                       |
| 심의/승인                | 북 승인 워크플로 패턴 재사용(3단계)                                        |

## 1단계 — 구좌 위젯 + 캠페인 기본기 — ✅ 구현됨(2026-08-25)

- [x] 계획 문서
- [x] 스키마(마이그레이션 0017): `creta_advertiser`, `creta_ad_campaign`(기간·상태 live/paused·가중치 1~10·CPM), `creta_ad_creative`(image|video·src), `creta_ad_play_log`(이름 비정규화)
- [x] 광고 위젯(adSlot): 팔레트 「광고」 — 속성 = 구좌 이름·슬롯 길이(5~120초)·빈 구좌 정책(하우스 광고/숨김).
      편집 모드는 플레이스홀더 카드(활성 소재 수 표시), 보기 모드는 활성 캠페인 소재를 슬롯 길이 공통 클록으로 순환
      (캠페인 가중치 = 로테이션 투입 횟수, 캠페인 라운드로빈으로 연속 방지), AD 라벨·캠페인명 표기, 소재 없으면 하우스 광고 카드
- [x] 광고 관리 메뉴(/ads): 광고주 등록/삭제 → 캠페인 생성/일시중지·재개/삭제 → 소재 추가(업로드 경로·https URL)/삭제(팝오버)
- [x] 재생 기록: 보기 모드에서 소재 표시 시 `creta_ad_play_log` 기록(epoch당 1회)
- [x] 리포트(기본): /ads 요약 카드(노출수·정산 예상액 30일) + 캠페인별 노출수·정산액
- 알려진 한계: React StrictMode 이중 마운트 시 로그가 간혹 중복될 수 있음(시뮬레이션 수준 허용)

## 노출 채널 결정(2026-08-25 합의)

광고 관리(광고주·캠페인·소재)는 하나로 두고, 노출 채널은 두 방식을 병행한다:

1. **존(위젯)형** — 북 캔버스의 광고 위젯(구좌). 콘텐츠와 동시 노출. ← 1단계
2. **루프(전체 화면)형** — 프레젠테이션 재생 중 N페이지마다 전체 화면 광고 스팟 자동 삽입
   - **광고 전용 재생**(디바이스 소스로 「광고」 선택 = 활성 소재 100% 루프). ← 2단계
     이로써 디바이스 재생 소스는 북·플레이리스트·스케줄·광고 4종이 된다.

## 2단계 — 루프 삽입 + 편성 고도화 + 리포트/정산 — ✅ 구현됨(2026-08-25)

- [x] 전체 화면 루프 삽입(마이그레이션 0018 `creta_ad_setting`): /ads 설정에서 "N페이지마다 1스팟"·스팟 길이(5~30초)
      지정 — 프레젠테이션이 N페이지 자동 진행할 때마다 전체 화면 스팟(AD 라벨·캠페인명) 삽입, 로그는 구좌 "loop"로 기록
- [x] 광고 전용 재생: 디바이스 재생 소스 4번째 탭 「광고」 — 지정 시 sourceType="ad"(광고 전용 루프).
      디바이스 재생 소스는 북·플레이리스트·스케줄·광고 4종
- [x] 요일(매일/평일/주말)·시간대(시작~종료 분) 타기팅 — 캠페인 생성 시 지정, 편성 필터에 반영
- [x] 하우스 광고 관리: /ads 설정에서 이름·종류·소재 URL 지정 → 빈 구좌를 하우스 소재(HOUSE 라벨)로 채움
- [x] 재생 리포트 광고 섹션: 캠페인별 노출·노출 시간·정산 예상액(노출수×CPM), 시간대(0~23시) 분포 바, 구좌별 집계
- [x] 캠페인 단계 파생 표시: 예정(scheduled) → 라이브/일시중지 → 종료(ended) — 기간 기준 자동
- 3단계로 이동: SOV(%) 점유율 보장·시간당 재생 상한·디바이스 태그 타기팅(위젯이 디바이스 문맥을 모르는 시뮬레이션 한계)

## 3단계 — 운영 워크플로 — ✅ 구현됨(2026-08-25)

- [x] 소재 심의(마이그레이션 0019): 일반 사용자가 소재를 올리면 pending(심의 중) → 관리자가 소재 칩 팝오버에서
      승인(편성 투입)/반려. 관리자 업로드는 즉시 승인. 편성(listActiveCreatives)은 approved만
- [x] 감사 로그 `creta_ad_audit_log`: 광고주·캠페인·소재·설정의 등록/변경/삭제/승인/반려를 행위자와 함께 기록,
      /ads 「변경 이력」 팝오버(10초 자동 갱신)
- [x] 구좌 인벤토리(판매 가능량): 전체 북에서 광고 위젯을 스캔 — 구좌 이름·북·슬롯 길이·연결 디바이스 수·
      시간당 노출 능력(3600/슬롯 × max(1, 디바이스)) 표. 플레이리스트·스케줄 경유는 제외한 근사치
- [x] SOV(점유율) 표시: 라이브 캠페인 가중치 합 대비 % 를 캠페인 카드에 표시
- [x] 시간당 재생 상한: 캠페인 maxPerHour — 최근 1시간 노출수가 상한에 달한 캠페인은 편성에서 제외
- [x] 소재 썸네일·순서(마이그레이션 0020 position): 소재 칩에 이미지/영상 첫 프레임 미리보기,
      팝오버에서 앞/뒤 순서 이동(로테이션 순서 반영)
- 남김(선택): 광고주 계정 초대(자기 캠페인 리포트만 열람)
- 디바이스 태그 타기팅 → **4단계에서 구현됨** ([creta-ad-targeting-plan-2026-08.md](creta-ad-targeting-plan-2026-08.md)).
  "위젯이 디바이스 문맥을 모른다"는 제약은 프레젠테이션에 `?device=` 를 넘겨 해소했다.

## 4단계 — 화면(디바이스) 타기팅 — ✅ 구현됨(2026-08-26)

캠페인을 어느 화면에 내보낼지 정하는 축. 자세한 배경·설계는
[creta-ad-targeting-plan-2026-08.md](creta-ad-targeting-plan-2026-08.md) 참고.

- [x] 캠페인 대상 화면(디바이스 태그) — `creta_ad_campaign_target`(마이그레이션 0022).
      대상이 비면 전체 화면 대상(기존 캠페인 호환)
- [x] 편성 필터에 화면 문맥 반영 — `listActiveCreatives({ deviceId })`
- [x] 노출 로그에 화면 기록 — `creta_ad_play_log.deviceId/deviceName`, 리포트에 「화면별 노출」 추가
- [x] 광고 전용 루프가 실제로 순환하고 노출을 기록 + 재생 이력에도 집계(`contentKind="ad"`)
- [x] 인벤토리를 "화면 × 시간" 기준으로 재구성 — 플레이리스트·스케줄 경유 구좌까지 포함

## 참고

- 표준 루프에 광고 6~8개, 캠페인 flight 보통 4주, 과금은 CPM·SOV·루프 빈도 방식이 일반적
- 프로그래매틱(SSP 연동 실시간 입찰)은 범위 밖 — 직접 판매 네트워크 수준까지만 구현
